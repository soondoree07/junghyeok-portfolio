**속성 과정 3일차이자 엑셀 마지막 날이에요.** 원래 11~15일차(확률·기대값·천장, 시뮬레이션, 성장 곡선, 스타포스, 미니 과제)를 하루로 압축했어요. 성장 곡선은 어제 `곡선` 시트에서 했으니 오늘은 **확률**에 집중해요. 단계마다 **풀어 보기**에 수식을 조각내고 숫자를 직접 넣어 계산해 뒀어요.

시작 파일에는 5일차 정답 상태에 아래가 더해져 있어요.

- 5일차 실습 과제(잘못된 보상 두 행 고치기)는 **고친 상태**로 들어 있어요
- `설정` 7~9행: 성공확률 `0.03`, 천장 `100`, 교체비용 `300000` (이름은 아직 없어요)
- `확률`: 이벤트 상자 확률표 6행(A3:C9), 시도 횟수 1~200(J4:J203), 목표 확률 50%·90%·99%(M4:M6), 천장 계산 이름표(M8:M10)
- `시뮬`: A2:A1001에 회차 1~1000, 결과 이름표(F2:F7), 요약 이름표(F9:F10)
- `스타포스`: 10~14단계의 성공확률·파괴확률·1회비용(A3:D8)

> **가정 수치 안내** 확률·비용은 모두 학습용 가정 값이에요. 실제 게임 값은 공식 확률 공개 페이지에서 직접 확인해요. 포트폴리오에 쓸 때도 "가정 수치"라고 꼭 적어요.

## 개념 설명

### 확률을 숫자로 쓰는 법

| 말 | 엑셀에 넣는 값 |
|---|---|
| 40% | `0.4` |
| 3% | `0.03` |
| 반드시 일어남 (100%) | `1` |
| 절대 안 일어남 | `0` |

- 확률은 **0과 1 사이 소수**로 넣어요. `3`을 넣으면 "300%"가 돼서 계산이 다 깨져요. 보이는 건 백분율 서식(<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>%</kbd>)으로 바꿔요
- **실패 확률 = 1 - 성공 확률**. 3% 성공이면 실패는 0.97이에요
- **연속으로 일어날 확률 = 곱하기**. 두 번 연속 실패 = 0.97 × 0.97 = 0.97^2

### 기대값 — "평균적으로 얼마짜리인가"

```text
기대값 = (결과1 가치 × 확률1) + (결과2 가치 × 확률2) + …
```

오늘 이벤트 상자로 직접 계산하면 이래요.

| 결과 | 가치 | 확률 | 가치 × 확률 |
|---|---|---|---|
| 회복 물약(소) | 50 | 0.4 | 20 |
| 이동 주문서 | 400 | 0.25 | 100 |
| 예시 강화석 | 2,600 | 0.2 | 520 |
| 예시 큐브 조각 | 9,000 | 0.1 | 900 |
| 예시 반지 | 25,000 | 0.04 | 1,000 |
| 예시 무기 상자 | 88,000 | 0.01 | 880 |
| **합계 = 기대값** | | **1** | **3,420** |

- 뜻: 이 상자를 아주 많이 열면 **한 개당 평균 3,420메소어치**가 나와요. 상자 가격이 3,420보다 비싸면 평균적으로 손해예요
- 엑셀에서는 `SUMPRODUCT(확률범위, 가치범위)` 한 번이면 돼요. 이름 그대로 **곱(PRODUCT)해서 더해(SUM)** 줘요. 위 표의 오른쪽 열을 만들고 더하는 걸 한 칸에서 해요
- 확률표는 **확률 합이 정확히 1**인지 꼭 검사해요. 합이 1이 아니면 기대값도 틀려요

### 누적확률 — "n번 안에 한 번이라도 성공할 확률"

"3%짜리를 100번 하면 한 번은 되겠지?"를 계산하는 법이에요. **한 번 이상 성공**을 바로 세면 복잡해서, 반대인 **전부 실패**를 구해서 1에서 빼요.

| 식 | 뜻 | p=3%, n=100 |
|---|---|---|
| `(1-p)^n` | n번 **모두 실패**할 확률 (0.97을 n번 곱함) | 0.97^100 ≈ 4.8% |
| `1-(1-p)^n` | n번 안에 **한 번 이상 성공**할 확률 | 1 - 4.8% ≈ 95.2% |
| `ROUNDUP(LN(1-목표)/LN(1-p),0)` | 목표 확률에 필요한 시도 횟수 | 목표 50% → 23회 |
| `1/p` | 평균 시도 횟수 | 1 / 0.03 ≈ 33.3회 |

- 3% 확률을 100번 해도 100%가 아니에요. 약 95%예요. 100명 중 5명은 100번 해도 못 얻어요
- **평균 33회인데 50% 확률은 23회?** 둘은 다른 질문이에요. 23회면 절반은 이미 성공해요. 하지만 운 나쁜 사람이 100회, 150회까지 가서 평균을 33회로 끌어올려요

**필요 횟수 식 `LN(1-목표)/LN(1-p)` 은 이렇게 나와요**

"전부 실패할 확률이 (1-목표) 이하가 되는 n"을 찾는 거예요. 목표 50%면 0.97^n ≤ 0.5가 되는 n이에요.

- n이 지수 자리에 있어서 그냥은 못 꺼내요. `LN`(자연로그)은 **지수를 앞으로 꺼내 주는 함수**예요: LN(0.97^n) = n × LN(0.97)
- 그래서 n = LN(0.5) / LN(0.97) = (-0.693) / (-0.0305) ≈ 22.76
- 횟수는 정수라 **올려서** 23회예요(22회면 아직 50%가 안 돼요)
- LN의 원리까지 외울 필요는 없어요. "필요 횟수 = `ROUNDUP(LN(1-목표)/LN(1-p),0)`" 식을 그대로 가져다 쓰면 돼요

### 천장 — "N번째에는 반드시 성공"

| 계산 | 식 | p=3%, 천장 100 |
|---|---|---|
| 천장 없는 평균 시도 | `1/p` | 33.33회 |
| 천장 있는 평균 시도 | `(1-(1-p)^N)/p` | 31.75회 |
| 천장까지 가는 확률 | `(1-p)^(N-1)` | 약 4.9% |

- **천장까지 가는 확률**: 100번째에 가려면 앞의 99번을 모두 실패해야 해요 → 0.97^99 ≈ 4.9%. 20명 중 1명꼴이에요
- **천장 있는 평균**: 천장이 없으면 33.33회인데, 100회 넘게 걸릴 불운한 사람들이 100회에서 끊기니 평균이 조금 내려가요(31.75회)
- 천장은 평균은 조금만 줄이지만, **최악의 경우를 100회로 막아** 불운한 소수 유저를 지켜 줘요. 기획서에 천장을 넣을 땐 이 두 숫자(평균 변화, 천장 도달 비율)를 같이 적어요

### 시뮬레이션 — 실제로 1000번 돌려 보기

공식으로 구한 값이 맞는지, 엑셀에서 가상의 유저 1000명에게 직접 시켜 봐요.

| 함수 | 하는 일 |
|---|---|
| `RAND()` | 0 이상 1 미만 난수. 다시 계산할 때마다 바뀌어요 |
| 누적하한표 + `XLOOKUP(난수,하한,결과,,-1)` | 확률대로 결과 하나 뽑기 (4일차 근사 일치) |
| `ROUNDUP(LN(RAND())/LN(1-p),0)` | 성공까지 걸린 시도 횟수 하나 뽑기 |
| `PERCENTILE.INC(범위,0.9)` | 상위 10% 불운 유저의 시도 횟수 |

**난수로 확률대로 뽑는 원리 (누적하한)**

0~1 사이를 확률 크기만큼 칸으로 나눠요. 난수가 떨어진 칸이 결과예요.

```text
0        0.4       0.65     0.85   0.95  0.99 1
|--물약--|--주문서--|--강화석-|-큐브-|반지|무기|
  40%       25%       20%     10%   4%   1%
```

- 각 칸의 **시작점**이 누적하한이에요: 0, 0.4, 0.65, 0.85, 0.95, 0.99
- 난수 0.97 → 0.95 이상 0.99 미만 → 예시 반지
- "시작점 표에서 내 값보다 작거나 같은 것 중 가장 가까운 것" = 4일차 레벨 구간 판정과 똑같은 XLOOKUP `-1`이에요

난수가 많으면 입력할 때마다 느려져요. **수식 > 계산 옵션 > 수동**으로 바꾸고 <kbd>F9</kbd>를 눌러 다시 계산해요.

## 따라 하기

1. **시작 파일 열고 이름 붙이기**
   시작 파일을 열고 <kbd>F12</kbd>로 `excel-06_probability.xlsx`로 저장해요.
   `설정` 시트 B7, B8, B9에 어제처럼 이름 상자로 `성공확률`, `천장`, `교체비용` 이름을 붙여요.

2. **상자 가치와 기대값**
   `확률` 시트로 가요. D4에 아래 수식을 넣고 D9까지 채워요.

   ```text
   =XLOOKUP(B4,아이템!$A:$A,아이템!$F:$F,0)
   ```

   H3, H4, H5에 차례로 넣어요.

   ```text
   =SUM(C4:C9)
   =IF(ABS(H3-1)<0.000000001,"OK","확률 합 오류")
   =SUMPRODUCT(C4:C9,D4:D9)
   ```

**풀어 보기: 세 수식**

| 칸 | 수식 | 말로 풀면 |
|---|---|---|
| D4 | `XLOOKUP(B4,아이템!$A:$A,아이템!$F:$F,0)` | 이 결과의 item_id로 아이템 시트에서 판매가를 가져와요(4일차·5일차와 같은 수식) |
| H3 | `SUM(C4:C9)` | 확률 6개를 더해요 → 1이어야 해요 |
| H4 | `IF(ABS(H3-1)<0.000000001,"OK","확률 합 오류")` | H3이 1과 거의 같으면 OK |
| H5 | `SUMPRODUCT(C4:C9,D4:D9)` | C4×D4 + C5×D5 + … + C9×D9 = 기대값 |

**H4는 왜 `=1`로 비교하지 않나**

- 컴퓨터는 0.1, 0.2 같은 소수를 아주 조금 틀리게 저장해요. 0.4+0.25+0.2+0.1+0.04+0.01을 더하면 화면엔 1인데 실제로는 0.9999999999999999일 수 있어요
- 그래서 "1과의 차이가 아주 작으면 같다고 친다"로 비교해요
- `H3-1`: 1과의 차이 (0.9999...면 -0.0000...1)
- `ABS(...)`: 부호를 떼요(절댓값). 차이가 +든 -든 크기만 봐요
- `<0.000000001`: 차이가 10억분의 1보다 작으면 → OK

**H5 `SUMPRODUCT`**: 개념 설명의 기대값 표 오른쪽 열(가치 × 확률)을 만들어 더하는 걸 한 칸에서 해요. 두 범위는 **크기가 같아야** 해요(둘 다 6칸).

> **체크포인트** D4:D9 = `50, 400, 2600, 9000, 25000, 88000`, H3 = `1`, H4 = `OK`, H5 = `3420`이에요.

3. **누적확률 표**
   K4에 넣고 K203까지 채워요(채우기 핸들 더블클릭).

   ```text
   =1-(1-성공확률)^J4
   ```

   K열을 백분율로 표시해요(<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>%</kbd>).

**풀어 보기: `1-(1-성공확률)^J4`**

| 조각 | J4 = 2일 때 |
|---|---|
| `1-성공확률` | 1 - 0.03 = 0.97 (한 번 실패할 확률) |
| `(...)^J4` | 0.97^2 = 0.9409 (2번 모두 실패) |
| `1-(...)` | 1 - 0.9409 = 0.0591 → 약 5.9% (2번 안에 한 번 이상 성공) |

- J열 = 시도 횟수(1~200)예요. 아래로 채우면 J5, J6…으로 바뀌어 횟수별 확률이 쭉 나와요
- `성공확률`은 이름이라 `$`가 필요 없어요
- 괄호를 빼고 `1-1-성공확률^J4`로 쓰면 계산 순서가 바뀌어 엉뚱한 값이 나와요. `(1-성공확률)` 괄호는 꼭 넣어요

> **체크포인트** K26(23회) = `50%`, K79(76회) = `90%`, K103(100회) = `95%`예요(소수 첫째 자리까지 보면 50.3%, 90.1%, 95.2%).

4. **목표 확률별 필요 횟수**
   N4에 넣고 N6까지 채워요.

   ```text
   =ROUNDUP(LN(1-M4)/LN(1-성공확률),0)
   ```

**풀어 보기: `ROUNDUP(LN(1-M4)/LN(1-성공확률),0)`**

| 조각 | M4 = 0.5일 때 |
|---|---|
| `1-M4` | 1 - 0.5 = 0.5 (허용할 "전부 실패" 확률) |
| `LN(1-M4)` | LN(0.5) ≈ -0.693 |
| `LN(1-성공확률)` | LN(0.97) ≈ -0.0305 |
| 나누기 | -0.693 ÷ -0.0305 ≈ 22.76 |
| `ROUNDUP(...,0)` | 올려서 23 |

- 원리는 개념 설명의 "필요 횟수 식"에 있어요. 식 자체는 외워서 써도 돼요
- 3단계 표로 검산해요: K25(22회)는 50% 미만, K26(23회)에서 처음 50%를 넘어요

> **체크포인트** N4:N6 = `23, 76, 152`예요. 3단계 표에서 그 횟수에서 처음 목표를 넘는지 확인해요.

5. **천장 효과**
   N8, N9, N10에 차례로 넣어요.

   ```text
   =1/성공확률
   =(1-(1-성공확률)^천장)/성공확률
   =(1-성공확률)^(천장-1)
   ```

**풀어 보기: 천장 세 수식**

| 칸 | 수식 | 계산 | 뜻 |
|---|---|---|---|
| N8 | `1/성공확률` | 1 ÷ 0.03 = 33.33 | 천장 없을 때 평균 시도 |
| N9 | `(1-(1-성공확률)^천장)/성공확률` | (1 - 0.97^100) ÷ 0.03 ≈ 0.952 ÷ 0.03 = 31.75 | 천장 100이 있을 때 평균 시도 |
| N10 | `(1-성공확률)^(천장-1)` | 0.97^99 ≈ 0.049 | 99번 연속 실패해 천장까지 갈 확률 |

- N9 식은 "100번 안에 성공할 확률(3단계 K103 값) ÷ 성공확률"이에요. 원리까지 알 필요는 없고, 천장이 있으면 평균이 **조금** 줄어든다는 것만 기억해요
- N10이 `천장-1`인 이유: 천장이 100이면 100번째는 무조건 성공이니, "천장까지 갔다" = 1~99번째가 모두 실패예요

> **체크포인트** N8 = `33.33`, N9 = `31.75`, N10 = `4.9%`예요. `설정` B7을 `0.01`로 바꿔 보면 N8 = `100`, N9 = `63.4`로 천장 효과가 훨씬 커져요. 확인했으면 `0.03`으로 돌려놓아요.

6. **누적하한 만들기 (뽑기 준비)**
   `확률` 시트 E열(누적하한)의 E4에 `0`, E5에 `=E4+C4`를 넣고 E9까지 채워요.

**풀어 보기: `=E4+C4`**

"바로 위 칸의 시작점 + 바로 위 칸의 확률 = 내 시작점"이에요.

| 행 | 결과 | 확률(C) | 누적하한(E) | 계산 |
|---|---|---|---|---|
| 4 | 회복 물약(소) | 0.4 | 0 | 직접 입력 |
| 5 | 이동 주문서 | 0.25 | 0.4 | 0 + 0.4 |
| 6 | 예시 강화석 | 0.2 | 0.65 | 0.4 + 0.25 |
| 7 | 예시 큐브 조각 | 0.1 | 0.85 | 0.65 + 0.2 |
| 8 | 예시 반지 | 0.04 | 0.95 | 0.85 + 0.1 |
| 9 | 예시 무기 상자 | 0.01 | 0.99 | 0.95 + 0.04 |

- 개념 설명의 0~1 막대 그림에서 각 칸의 시작점이에요
- E4를 0으로 둬야 난수가 0.0~0.4 사이일 때 물약이 나와요. 비워 두면 그 구간을 못 찾아요

> **체크포인트** E4:E9 = `0, 0.4, 0.65, 0.85, 0.95, 0.99`예요. 난수가 0.97이면 0.95 이상 0.99 미만이라 `예시 반지`가 나와요.

7. **계산 옵션 수동으로**
   **수식 > 계산 옵션 > 수동**을 골라요. 이제부터 다시 계산하려면 <kbd>F9</kbd>를 눌러요.

**풀어 보기: 왜 수동으로 바꾸나**

- `RAND()`는 엑셀이 다시 계산할 때마다 새 난수를 뽑아요. 아무 칸에 글자 하나만 입력해도 다시 계산돼요
- 다음 단계에서 RAND를 2,000칸(B열 1,000 + D열 1,000)에 넣으면, 입력할 때마다 2,000개를 새로 뽑느라 느려지고 값이 계속 바뀌어 확인하기 어려워요
- 수동으로 두면 <kbd>F9</kbd>를 누를 때만 다시 뽑아요. **끝나면 꼭 자동으로 되돌려요**(11단계). 안 그러면 다른 파일에서도 수식이 안 바뀌어 헷갈려요

8. **상자 1000번 열기**
   `시뮬` 시트 B2, C2에 아래 수식을 넣고 1001행까지 채운 뒤 <kbd>F9</kbd>를 눌러요.

   ```text
   =RAND()
   =XLOOKUP(B2,확률!$E$4:$E$9,확률!$A$4:$A$9,,-1)
   ```

   G2에 `=COUNTIF($C$2:$C$1001,F2)/1000`을 넣고 G7까지 채운 뒤 백분율로 표시해요.

**풀어 보기: 뽑기 수식**

`XLOOKUP(B2,확률!$E$4:$E$9,확률!$A$4:$A$9,,-1)`

| 칸 | 넣은 것 | 뜻 |
|---|---|---|
| 찾을값 | `B2` | 이 회차의 난수 |
| 찾을범위 | `확률!$E$4:$E$9` | 누적하한 (각 칸의 시작점) |
| 가져올범위 | `확률!$A$4:$A$9` | 결과 이름 |
| 없을때값 | (비움) | `,,`처럼 쉼표 사이를 비우면 "안 씀"이에요 |
| 일치모드 | `-1` | 같은 값이 없으면 바로 아래(작은) 값 |

- 4일차 레벨 구간 판정과 똑같은 구조예요. 레벨 대신 난수, 하한레벨 대신 누적하한이에요
- 없을때값을 비우려고 쉼표 두 개(`,,`)를 붙여 썼어요. 일치모드가 다섯 번째 칸이라 네 번째 칸을 건너뛰어야 해서예요
- `$E$4:$E$9`처럼 범위를 행·열 모두 고정해요. 1,001행까지 내려도 확률표 위치는 그대로여야 해요

`COUNTIF($C$2:$C$1001,F2)/1000`

- C열 1,000개 결과 중 F2(회복 물약(소))가 몇 번 나왔나 ÷ 1,000 = 실제로 나온 비율
- 확률표의 40%와 비교해서 "정말 확률대로 뽑히나" 확인하는 거예요

> **체크포인트** G2:G7이 대략 `40%, 25%, 20%, 10%, 4%, 1%` 근처예요. 난수라서 정확히 같지는 않아요. <kbd>F9</kbd>를 몇 번 눌러 얼마나 흔들리는지 봐요.

9. **성공까지 걸린 횟수 1000명분**
   D2에 넣고 1001행까지 채워요.

   ```text
   =MIN(천장,ROUNDUP(LN(RAND())/LN(1-성공확률),0))
   ```

   G9에 `=AVERAGE(D2:D1001)`, G10에 `=PERCENTILE.INC(D2:D1001,0.9)`를 넣고 <kbd>F9</kbd>를 눌러요.

**풀어 보기: `MIN(천장,ROUNDUP(LN(RAND())/LN(1-성공확률),0))`**

안쪽부터 읽어요.

| 조각 | 뜻 |
|---|---|
| `ROUNDUP(LN(RAND())/LN(1-성공확률),0)` | 유저 한 명이 3% 확률로 **몇 번째에 성공하는지** 한 번에 뽑아요 |
| `MIN(천장, ...)` | 그 값이 100보다 크면 100으로 잘라요 (천장) |

- 4단계 필요 횟수 식에서 `1-목표` 자리에 `RAND()`를 넣은 모양이에요. 난수가 0.5면 23회, 0.1이면 76회, 0.9면 4회처럼 나와요
- 유저마다 실제로 1번, 2번… 시도하며 굴리면 칸이 너무 많이 필요해요. 이 식은 그걸 **한 칸에서** 해 주는 요령이에요. 원리는 몰라도 되고, "성공까지 횟수 뽑기 = 이 식"으로 가져다 써요
- `MIN(A, B)`은 둘 중 작은 값이에요. 뽑힌 횟수가 130이면 MIN(100, 130) = 100

**G9, G10**

| 칸 | 수식 | 뜻 |
|---|---|---|
| G9 | `AVERAGE(D2:D1001)` | 1,000명의 평균 시도 횟수 → 5단계 N9(31.75)와 비교 |
| G10 | `PERCENTILE.INC(D2:D1001,0.9)` | 1,000명을 횟수 순으로 줄 세웠을 때 90% 지점의 값 |

- PERCENTILE.INC 결과가 76이면 "**10명 중 9명은 76회 안에** 성공하고, 1명은 76회보다 더 걸린다"는 뜻이에요
- 0.9 대신 0.5를 넣으면 가운데 사람(중앙값), 0.99를 넣으면 100명 중 가장 운 나쁜 1명 근처예요

> **체크포인트** G9가 5단계 N9(`31.75`) 근처(대략 29~35), G10이 4단계 N5(`76`) 근처예요. 평균은 32회인데 10명 중 1명은 76회 넘게 걸려요. 기획서에는 **평균과 불운 구간을 같이** 적어요.

10. **스타포스 단계별 기대 비용**
    `스타포스` 시트 E4:I4에 아래 수식을 넣고 8행까지 채워요. 파괴되면 교체비용을 내고 **같은 단계에서 다시 시도**한다고 가정한 단순 모델이에요.

    ```text
    =1-B4-C4
    =1/B4
    =F4*C4
    =ROUND(F4*D4+G4*교체비용,0)
    =SUM($H$4:H4)
    ```

    차례로 실패확률, 기대시도, 기대파괴, 단계비용, 누적비용이에요.

**풀어 보기: 12단계(6행)에 숫자를 넣어 보면**

12단계 = 성공 0.4, 파괴 0.02, 1회비용 30,000이에요.

| 칸 | 수식 | 계산 | 뜻 |
|---|---|---|---|
| E 실패확률 | `1-B4-C4` | 1 - 0.4 - 0.02 = 0.58 | 성공도 파괴도 아닌 그냥 실패 |
| F 기대시도 | `1/B4` | 1 ÷ 0.4 = 2.5회 | 성공까지 평균 시도 (개념 설명 `1/p`) |
| G 기대파괴 | `F4*C4` | 2.5 × 0.02 = 0.05번 | 2.5번 시도하는 동안 평균 파괴 횟수 |
| H 단계비용 | `ROUND(F4*D4+G4*교체비용,0)` | 2.5 × 30,000 + 0.05 × 300,000 = 75,000 + 15,000 = 90,000 | 시도 비용 + 파괴 비용 |
| I 누적비용 | `SUM($H$4:H4)` | 10~12단계 단계비용 합 | 10단계부터 여기까지 총비용 |

- 결과는 성공·실패·파괴 세 가지라 세 확률을 더하면 1이에요. 그래서 실패 = 1 - 성공 - 파괴
- 기대파괴 0.05번 = "20번에 1번꼴로 이 단계에서 장비가 터진다"는 뜻이에요. 터질 때마다 교체비용 300,000을 내니 평균 15,000이 더 들어요

**누적비용 `SUM($H$4:H4)` — 늘어나는 범위**

| 행 | 수식 | 더하는 범위 |
|---|---|---|
| 4 | `SUM($H$4:H4)` | H4 |
| 5 | `SUM($H$4:H5)` | H4~H5 |
| 6 | `SUM($H$4:H6)` | H4~H6 |
| 8 | `SUM($H$4:H8)` | H4~H8 |

- 범위의 **시작 칸만 `$`로 고정**하고 끝 칸은 풀어 뒀어요. 아래로 채우면 끝 칸만 내려가서 범위가 점점 늘어나요
- 시작 칸에도 `$`가 없으면 `SUM(H5:H5)`, `SUM(H6:H6)`처럼 같이 내려가서 단계비용과 똑같아져요
- "지금까지의 합계(누계)"가 필요할 때 늘 쓰는 모양이에요. 일차별 누적 획득량, 누적 매출 등에도 써요

> **체크포인트** H4:H8 = `40000, 55556, 90000, 125714, 173333`, I8 = `484603`이에요. 단계가 오를수록 성공확률은 떨어지고 파괴가 붙어서 비용이 빠르게 늘어요.

11. **계산 옵션 되돌리고 저장**
    **수식 > 계산 옵션 > 자동**으로 돌려놓고 <kbd>Ctrl</kbd>+<kbd>S</kbd>로 저장해요.

## 실습 과제 (엑셀 미니 과제)

이 파일을 **처음 보는 사람도 믿고 쓸 수 있는 워크북**으로 마무리해요. 포트폴리오에 넣을 결과물이에요.

**1. `검증` 시트** (<kbd>Shift</kbd>+<kbd>F11</kbd>로 새 시트를 만들고 이름을 `검증`으로 바꿔요)

- A1:B1에 `검사, 결과`
- A2 `확률 합` / B2 `=확률!H4`
- A3 `보상 참조` / B3 `=IF(COUNTIF(보상!$F$2:$F$13,"?*")=0,"OK","수정 필요")`
- A4 `중복 ID` / B4 `=IF(SUMPRODUCT(--(COUNTIF(아이템!$A$2:$A$21,아이템!$A$2:$A$21)>1))=0,"OK","수정 필요")`
- A6 `최종` / B6 `=IF(COUNTIF(B2:B4,"OK")=3,"배포 가능","수정 필요")` — 글자를 크게, 조건부 서식으로 `배포 가능`이면 초록, 아니면 빨강

**풀어 보기: B3 `COUNTIF(보상!$F$2:$F$13,"?*")=0`**

- 보상 시트 F열은 5일차 참조 검사 열이에요. 문제가 없으면 빈 칸, 있으면 `없는 아이템`·`없는 그룹`이 적혀요
- `"?*"`는 와일드카드예요. `?` = **딱 한 글자**, `*` = 아무 글자나 몇 글자든(0글자도). 합치면 "**한 글자 이상** 적힌 칸"이에요
- 그래서 COUNTIF 결과 = 문제가 적힌 행 개수예요. 0이면 OK
- 그냥 `"*"`는 왜 안 쓰나: F열 칸은 수식이 `""`(빈 글자)를 돌려주는 칸이라, `"*"`(0글자도 됨)로 세면 빈 칸처럼 보이는 칸까지 세어질 수 있어요. `"?*"`로 "진짜 글자가 있는 칸"만 세요

**풀어 보기: B4 중복 ID 검사 (가장 어려운 수식)**

안쪽부터 네 겹으로 읽어요. ID가 4개뿐인 작은 예(IT001, IT002, IT002, IT003)로 보면 이래요.

| 순서 | 조각 | 결과 |
|---|---|---|
| 1 | `COUNTIF(A2:A5, A2:A5)` | 각 ID가 몇 번 나오나를 **한꺼번에** → `1, 2, 2, 1` |
| 2 | `(...)>1` | 2번 이상 나왔나 → `FALSE, TRUE, TRUE, FALSE` |
| 3 | `--(...)` | TRUE는 1, FALSE는 0으로 → `0, 1, 1, 0` |
| 4 | `SUMPRODUCT(...)` | 다 더해요 → `2` (중복된 칸이 2개) |

- 1단계가 핵심이에요. 4일차에는 COUNTIF 조건 칸에 셀 하나(`A2`)를 넣었는데, 여기선 **범위 전체**를 넣었어요. 그러면 엑셀이 칸마다 따로 세어 숫자 여러 개를 돌려줘요
- `--`(빼기 두 번): TRUE/FALSE에 빼기를 두 번 하면 1/0 숫자가 돼요. 숫자여야 더할 수 있어요
- SUMPRODUCT는 여러 값을 한 번에 더할 때 써요. 여기선 곱할 짝 없이 범위 하나만 줬어요
- 결과가 0이면 겹치는 ID가 없다는 뜻 → OK

**풀어 보기: B6 최종**

- `COUNTIF(B2:B4,"OK")`: B2~B4 중 `OK`가 몇 개인가
- `=3`: 세 검사가 모두 OK면 "배포 가능"
- 조건부 서식: B6 선택 → **홈 > 조건부 서식 > 셀 강조 규칙 > 같음** → `배포 가능` → 초록 채우기. 규칙을 하나 더 만들어 `수정 필요`면 빨강

**2. 고장 내 보기:** `확률` C4를 `0.5`로 바꿔 B6이 `수정 필요`로 바뀌는지 확인하고 `0.4`로 되돌려요. (확률 합이 1.1이 되어 H4가 `확률 합 오류` → B2도 그 글자 → OK가 2개뿐이라 수정 필요)

**3. `README` 시트** — 시트 탭을 맨 왼쪽으로 끌어 옮기고 아래를 적어요.

- 목적 한 줄 (예: 가상 가을 이벤트 보상·확률 설계 워크북)
- 시트별 역할 표: `설정`, `아이템`, `보상그룹`, `보상`, `확률`, `시뮬`, `스타포스`, `검증` 각 한 줄
- ID 규칙: IT = 아이템, RG = 보상그룹, RW = 보상
- 가정: 모든 확률·비용은 학습용 가정 값, 실제 값으로 바꾸려면 `설정`과 `확률` 표만 고치면 됨

**README 예시 (시트별 역할 표 일부)**

| 시트 | 역할 |
|---|---|
| 설정 | 배율·확률·비용 같은 조정값 모음. 값을 바꾸면 모든 계산이 따라 바뀜 |
| 확률 | 이벤트 상자 확률표, 기대값(H5), 누적확률·천장 계산 |
| 검증 | 확률 합·참조·중복 ID 자동 검사, B6이 "배포 가능"이면 통과 |

나머지 시트도 같은 식으로 한 줄씩 적어요. "이 시트를 열면 뭐가 있고, 어떤 숫자를 보면 되는지"가 들어가면 돼요.

완성 기준: 검증 B2:B4 모두 `OK` · B6 = `배포 가능` · C4를 바꾸면 `수정 필요`로 바뀜 · README만 읽고 상자 기대값(`확률!H5` = 3420)을 찾아갈 수 있음.

## 자주 하는 실수와 해결법

| 증상 | 원인 | 해결 |
|---|---|---|
| 확률 합이 1인데 `확률 합 오류`가 떠요 | 소수 계산의 아주 작은 오차예요 | `=1` 대신 `ABS(합-1)<0.000000001`로 비교해요 |
| 누적확률이 모두 `0`이나 `1`이에요 | 성공확률을 `3`(퍼센트 숫자)으로 넣었어요 | 확률은 `0.03`처럼 소수로 넣어요 |
| 누적확률 값이 이상해요 | `1-(1-성공확률)^J4`에서 괄호를 빠뜨렸어요 | `(1-성공확률)` 괄호를 꼭 넣어요 |
| 뽑기 결과가 한 종류만 나오거나 `#N/A`예요 | XLOOKUP 마지막 `-1`을 빼서 정확히 같은 값만 찾았어요 | `,,-1`로 근사 일치를 넣어요 |
| 뽑기에서 물약이 안 나와요 | 누적하한 E4를 비웠어요 | E4에 `0`을 넣어요 |
| 시트가 입력할 때마다 느려요 | RAND가 천 칸 넘게 계속 다시 계산돼요 | 계산 옵션을 **수동**으로 두고 <kbd>F9</kbd>로 계산해요 |
| 수식을 고쳤는데 값이 안 바뀌어요 | 계산 옵션이 **수동**이에요 | <kbd>F9</kbd>를 누르거나 **자동**으로 되돌려요 |
| 시뮬 평균이 이론값과 조금 달라요 | 난수라서 정상이에요 | <kbd>F9</kbd>로 여러 번 돌려 근처에서 흔들리는지 봐요. 크게 다르면 수식을 의심해요 |
| 누적비용이 단계비용과 똑같아요 | `SUM(H4:H4)`처럼 시작 칸에 `$`가 없어요 | `SUM($H$4:H4)`로 시작 칸만 고정해요 |
| 중복 ID 검사가 늘 `수정 필요`예요 | 범위에 머리글(A1)이나 빈 칸까지 넣었어요 | `$A$2:$A$21`처럼 ID가 있는 칸만 넣어요 |
| `PERCENTILE.INC`가 `#NAME?`이에요 | 함수 이름 오타이거나 아주 옛 버전이에요 | 이름을 확인하거나 `PERCENTILE`을 써요 |
